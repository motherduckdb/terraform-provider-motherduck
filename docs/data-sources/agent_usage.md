# motherduck_agent_usage (Data Source)

Reads agent usage for the organization from `MD_INFORMATION_SCHEMA.AGENT_USAGE`. Each row covers one agent run, which is one turn of a MotherDuck agent chat, and reports the AI units it used. Requires a Business plan and query history access, which organization admins have. Rows are sorted by run finish time, session ID, and run sequence. Set `start_time` to bound long histories.

Agent usage is stored with query history, so MotherDuck returns it only on the
Business plan and only to principals with query history access. Organization
admins have that access. Configure the provider `token` (or `MOTHERDUCK_TOKEN`)
with such a principal. Other tokens fail the read with a query history access
error.

MotherDuck records one row per agent run. Set `start_time` and `end_time` to
read a bounded window, and use `limit` and `offset` to page through it. Both
bounds must be RFC 3339 timestamps with a time zone offset, such as
`2026-11-01T00:00:00Z`. A run is returned when it finished at or after
`start_time` and before `end_time`. AI units are reported as a decimal string.
Use `tonumber()` to add them up.

This data source requires a MotherDuck client that exposes `md_agent_usage`.
When the connected client does not, the read fails with a
`MotherDuck SQL function unavailable` error instead of returning no rows.
For Duckling compute usage, see [motherduck_compute_usage](compute_usage.md).

This data source inspects existing objects without taking lifecycle ownership.
Use it with credentials that can read them. See
[authentication](../guides/authentication.md).

## Example Usage

```terraform
# Requires a Business plan and a MotherDuck token with query history access,
# such as an organization admin token.
data "motherduck_agent_usage" "november" {
  start_time = "2026-11-01T00:00:00Z"
  end_time   = "2026-12-01T00:00:00Z"
}

output "ai_units_by_user" {
  value = {
    for user in distinct([for row in data.motherduck_agent_usage.november.rows : row.user_name]) :
    user => sum([for row in data.motherduck_agent_usage.november.rows : tonumber(row.ai_units) if row.user_name == user])
  }
}
```

## Schema

### Optional

- `end_time` (String) Optional RFC 3339 timestamp, for example `2026-11-02T00:00:00Z`. Returns only runs that finished before it. Must be later than `start_time` when both are set.
- `limit` (Number) Maximum number of rows to return. Rows are sorted before paging, so pages are stable.
- `offset` (Number) Number of sorted rows to skip before returning results.
- `start_time` (String) Optional RFC 3339 timestamp, for example `2026-11-01T00:00:00Z`. Returns only runs that finished at or after it.
- `username` (String) Optional MotherDuck user name. Returns only runs that the user started.

### Read-Only

- `rows` (Attributes List) Typed catalog rows for stable MotherDuck metadata. `rows_json` remains available for raw server columns. (see [below for nested schema](#nestedatt--rows))
- `rows_json` (String, Sensitive) Raw MotherDuck catalog rows encoded as JSON. Sensitive because catalog rows can include share URLs and account metadata.

### Nested Schema for `rows`

Read-Only:

- `ai_units` (String) AI units the run used, as a decimal string.
- `run_finished_ts` (String) Timestamp of the last model usage recorded for the run, which is approximately when the run finished.
- `run_seq` (String) Sequence number of the run within its session.
- `session_id` (String) UUID of the agent session. For the `chat` surface it is the chat ID.
- `surface` (String) Product surface the run came from, for example `chat`. Null for runs recorded before MotherDuck stored it.
- `user_id` (String) UUID of the user who started the run.
- `user_name` (String) Name of the user who started the run.
