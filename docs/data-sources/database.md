# motherduck_database (Data Source)

Reads one existing database from `MD_INFORMATION_SCHEMA.DATABASES` using the
configured SQL identity. Use this when another Terraform state or deployment
tool owns the database, and a downstream configuration needs its metadata.

The read fails if the exact name is absent from the caller's catalog or the
catalog query fails. A successful read confirms catalog visibility at refresh
time. It does not check table contents, restore data, or prove write access.
The data source never creates, imports, or drops the database.

Use `motherduck_databases` to discover multiple databases or accept an empty
result. Use the `motherduck_database` resource when this state owns the database.

## Example Usage

```terraform
# The warehouse is managed by another Terraform state or deployment tool.
data "motherduck_database" "warehouse" {
  name = "analytics"
}

output "warehouse_uuid" {
  value = data.motherduck_database.warehouse.uuid
}
```

For dependencies known during planning, Terraform reads this data source during
plan. Values that depend on pending resource changes can defer the read until
apply. Reference the returned attributes from downstream resources to establish
a Terraform dependency.

`historical_snapshot_retention` preserves the server's interval text and may be
null. It is not an integer day count. Database names are matched exactly and are
passed as SQL parameters.
