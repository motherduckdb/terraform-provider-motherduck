# motherduck_database_snapshots (Data Source)

Reads MotherDuck database snapshot metadata from public SQL catalog tables.

Rows mirror `MD_INFORMATION_SCHEMA.DATABASE_SNAPSHOTS`. When `database_name`
is set, MotherDuck can still return more than one row for that database,
including retained snapshots whose `snapshot_name` is null. Filter the typed
`rows` with a `for` expression when you need only named snapshots, as in the
example.

## Example Usage

```terraform
data "motherduck_database_snapshots" "analytics" {
  database_name = "analytics"
}

# Retained snapshots without a name report a null snapshot_name.
output "analytics_named_snapshots" {
  value = [
    for snapshot in data.motherduck_database_snapshots.analytics.rows :
    snapshot.snapshot_name if snapshot.snapshot_name != null
  ]
}
```

## Schema

### Optional

- `database_name` (String) MotherDuck database name filter.
- `limit` (Number) Maximum number of rows to return. Rows are sorted before paging, so pages are stable.
- `offset` (Number) Number of sorted rows to skip before returning results.

### Read-Only

- `rows` (Attributes List) Typed catalog rows for stable MotherDuck metadata. `rows_json` remains available for raw server columns. (see [below for nested schema](#nestedatt--rows))
- `rows_json` (String, Sensitive) Raw MotherDuck catalog rows encoded as JSON. Sensitive because catalog rows can include share URLs and account metadata.
