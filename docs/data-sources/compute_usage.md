# motherduck_compute_usage (Data Source)

Reads Duckling compute usage for the organization from `MD_INFORMATION_SCHEMA.COMPUTE_USAGE`. Each row covers one Duckling for one user in one 30-second window and reports its billable uptime and query count. Requires a Business plan and query history access, which organization admins have. Rows are sorted by window start, user name, and Duckling ID. Set `start_time` to bound long histories.

Compute usage comes from query history, so MotherDuck returns it only on the
Business plan and only to principals with query history access. Organization
admins have that access. Configure the provider `token` (or `MOTHERDUCK_TOKEN`)
with such a principal. Other tokens fail the read with a query history access
error.

MotherDuck records one row per Duckling, user, and 30-second window, so a
history grows quickly. Set `start_time` and `end_time` to read a bounded window,
and use `limit` and `offset` to page through it. Both bounds must be RFC 3339
timestamps with a time zone offset, such as `2026-11-01T00:00:00Z`. Uptime is
reported as a decimal string. Use `tonumber()` to add it up.

This data source requires a MotherDuck client that exposes
`md_compute_usage`. When the connected client does not, the read fails with a
`MotherDuck SQL function unavailable` error instead of returning no rows.

This data source inspects existing objects without taking lifecycle ownership.
Use it with credentials that can read them. See
[authentication](../guides/authentication.md).

## Example Usage

```terraform
# Requires a Business plan and a MotherDuck token with query history access,
# such as an organization admin token.
data "motherduck_compute_usage" "etl_yesterday" {
  username   = "etl_service"
  start_time = "2026-11-01T00:00:00Z"
  end_time   = "2026-11-02T00:00:00Z"
}

output "etl_uptime_seconds" {
  value = sum([for row in data.motherduck_compute_usage.etl_yesterday.rows : tonumber(row.uptime_seconds)])
}
```

## Schema

### Optional

- `end_time` (String) Optional RFC 3339 timestamp, for example `2026-11-02T00:00:00Z`. Returns only usage windows that end at or before it. Must be later than `start_time` when both are set.
- `limit` (Number) Maximum number of rows to return. Rows are sorted before paging, so pages are stable.
- `offset` (Number) Number of sorted rows to skip before returning results.
- `start_time` (String) Optional RFC 3339 timestamp, for example `2026-11-01T00:00:00Z`. Returns only usage windows that start at or after it.
- `username` (String) MotherDuck user or service-account principal.

### Read-Only

- `rows` (Attributes List) Typed catalog rows for stable MotherDuck metadata. `rows_json` remains available for raw server columns. (see [below for nested schema](#nestedatt--rows))
- `rows_json` (String, Sensitive) Raw MotherDuck catalog rows encoded as JSON. Sensitive because catalog rows can include share URLs and account metadata.

### Nested Schema for `rows`

Read-Only:

- `duckling_id` (String) Duckling ID. Can be empty when MotherDuck did not record one.
- `duckling_size` (String) Duckling size name, for example `Pulse` or `Standard`.
- `duckling_size_multiplier` (String) Billing multiplier of the Duckling size, for example `0.25` for Pulse and `1` for Standard.
- `end_time` (String) End of the 30-second usage window, exclusive.
- `is_read_scaling` (String) Whether the Duckling is a read-scaling replica, as `true` or `false`. Null when MotherDuck did not record it.
- `queries` (String) Number of queries the Duckling ran in the window.
- `start_time` (String) Start of the 30-second usage window, inclusive.
- `uptime_seconds` (String) Billable Duckling uptime in the window, in seconds, as a decimal string.
- `user_id` (String) UUID of the user or service account that used the Duckling.
- `user_name` (String) Name of the user or service account that used the Duckling.
