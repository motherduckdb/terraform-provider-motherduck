# motherduck_dive (Resource)

> **Deployment recommendation:** Use Terraform for databases, service accounts,
> access tokens, Duckling configuration, roles/grants, and shares. Keep Dives,
> Flight Python, and Guide Markdown in version control and deploy them through
> the MotherDuck CLI or a code deployment pipeline. Terraform apply does not
> compile application code, validate every data dependency, or run a data load.

See [resource scope and ownership migration](../guides/resource-scope.md).

Experimental: manage a Dive's content only when Terraform is its authoritative
owner. Prefer [Blueprints application deployments](../guides/blueprints-deployment.md)
for dashboard code, previews, and promotion.

## Usage and lifecycle

The example's unrestricted share is suitable only for data intended to be
accessible to anyone with its URL. For private or tenant data, design restricted
sharing and embedding access explicitly.

Import by Dive UUID. Refresh and import read `api_version` and the mounted
`required_resources` of the current Dive version from `MD_GET_DIVE`, so a mount
added, removed, or retargeted outside Terraform plans an update. MotherDuck
stores a share URL under the share's name. A configured share URL with the same
token keeps its configured spelling in state. After import, a configured URL
that names the same database or share but is spelled differently from the
stored one plans a single update that records the configured spelling without
writing a new Dive version. Omit
`api_version` to let MotherDuck choose it when content changes.

Each `required_resources` URL must start with `md:`. Mount a database as
`md:<database>` or a share with its share URL, for example from
`motherduck_share.url`. Refresh reports each mount's `resource_type`, either
`database` or `share`.

`version_description` describes the Dive version that Terraform writes.
MotherDuck stores it on the version, so changing it alone writes a new version
with the same content and mounts, and sends the current `api_version` unless
`api_version` is configured, so MotherDuck does not move the Dive to its
default API version. `MD_CREATE_DIVE` cannot set it, so setting it at creation
writes version 2 right after the Dive is created. If that second write fails,
the apply keeps the new Dive with a warning instead of tainting it, and the
next plan retries the write in place. When it is omitted, a content change
writes a version without a description.
`version_created_at` and `owner_id` are read from `MD_GET_DIVE`.

MotherDuck ignores an empty `description` in a metadata update, so an existing
description cannot be cleared in place. Setting it to `""` or removing it fails
the apply. Set a new non-empty description instead, or replace the Dive if it
must have none. Setting `endorsed` status requires the appropriate
organization-admin permission. MotherDuck sets the status of a new Dive after
creating it. If it rejects that status, the apply keeps the new Dive with a
warning instead of tainting it, and the next plan retries the status in place.
When an update writes new content and the status change then fails, the apply
fails but state records the written content, so the next apply retries only
the status and does not write the content again.

Destroy deletes the Dive. To change deployment tools without deleting it,
follow [ownership migration](../guides/resource-scope.md).

## Example Usage

```terraform
resource "motherduck_database" "wikipedia" {
  name = "wikipedia_pageviews"
}

resource "motherduck_share" "wikipedia" {
  name            = "wikipedia_pageviews"
  source_database = motherduck_database.wikipedia.name
  access          = "unrestricted"
  visibility      = "hidden"
  update_mode     = "automatic"
}

resource "motherduck_dive" "revenue" {
  title       = "Revenue"
  description = "Revenue overview"
  api_version = 1
  status      = "ready"

  required_resources = [
    {
      alias = "wikipedia_pageviews"
      url   = motherduck_share.wikipedia.url
    }
  ]

  content = <<-JSX
    export default function Dive() {
      return <div>Revenue</div>;
    }
  JSX
}
```

## Schema

### Required

- `content` (String) Dive content source sent to MotherDuck.
- `title` (String) Visible Dive title.

### Optional

- `api_version` (Number) Dive API version passed to MotherDuck when creating or updating content. Omit this to use the MotherDuck default when content or mounts change. A write that changes only `version_description` sends the current API version. Refresh and import read the current version's API version from `MD_GET_DIVE`.
- `description` (String) Optional Dive description. MotherDuck ignores an empty description in a metadata update, so an existing description cannot be cleared in place. Setting an existing description to an empty string or removing it is rejected. Replace the Dive to remove its description.
- `required_resources` (Attributes List, Sensitive) Optional databases or shares to mount into the Dive. Refresh and import read the current version's mounted resources from `MD_GET_DIVE`, so a mount changed outside Terraform plans an update. MotherDuck stores a share URL under the share's name. A configured URL that names the same share token keeps its spelling in state. (see [below for nested schema](#nestedatt--required_resources))
- `status` (String) Dive governance status. New Dives default to `draft`. Owners can set `draft`, `ready`, or `archived`, while `endorsed` requires organization-admin permission. If MotherDuck rejects the status of a new Dive, the apply keeps the Dive with a warning and the next plan retries the status in place.
- `version_description` (String) Description of the Dive version written by this configuration, sent as `description` to `MD_UPDATE_DIVE_CONTENT`. MotherDuck stores it on a version, so changing it writes a new Dive version with the same content. `MD_CREATE_DIVE` cannot set it, so setting it at creation writes a second version right away. Refresh and import read the current version's description from `MD_GET_DIVE`. When omitted, a content change writes a version without a description.

### Read-Only

- `created_at` (String) Dive creation timestamp reported by MotherDuck.
- `current_version` (Number) Current Dive version number reported by MotherDuck.
- `id` (String) Dive ID assigned by MotherDuck.
- `owner_id` (String) User UUID of the Dive owner reported by MotherDuck.
- `owner_name` (String) MotherDuck owner name for the Dive.
- `status_applies_to_version` (Number) Dive version reviewed when the status was last explicitly set.
- `status_changed_at` (String) Timestamp when the Dive status was last explicitly set.
- `status_set_by` (String) User UUID that last explicitly set the Dive status.
- `updated_at` (String) Dive update timestamp reported by MotherDuck.
- `version_created_at` (String) Creation timestamp of the current Dive version reported by MotherDuck.
