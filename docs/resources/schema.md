# motherduck_schema (Resource)

Create a namespace inside a database owned by the connected SQL account. Use
schemas to organize raw and analytical relations. A schema is not a separate
account or compute boundary.

## Usage and lifecycle

Reference the database resource's `.name` so Terraform orders creation and
destruction. The database and schema name are replacement-only.

Destroy is restrictive by default: unmanaged objects prevent removal. Set
`cascade_on_delete = true` only when removing every contained object is intended.
The setting can change without replacing the schema.

Import uses `<database>.<schema>`. The built-in `main` schema already exists in
a database. Reference it by name when appropriate rather than creating it again.

See [your first warehouse](../guides/getting-started.md).

## Example Usage

```terraform
resource "motherduck_database" "analytics" {
  name = "analytics"
}

resource "motherduck_schema" "mart" {
  database = motherduck_database.analytics.name
  name     = "mart"
}
```

## Schema

### Required

- `database` (String) Database that contains the schema.
- `name` (String) Schema name.

### Optional

- `cascade_on_delete` (Boolean) When true, uses `DROP SCHEMA ... CASCADE` during destroy. The default is restrictive and fails if the schema contains unmanaged objects.

### Read-Only

- `id` (String) Schema resource ID in `<database>.<schema>` form.
