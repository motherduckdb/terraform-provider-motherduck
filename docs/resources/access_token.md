# motherduck_access_token (Resource)

Creates and revokes a MotherDuck access token for a user or service account.
The token secret is returned only when the token is created and cannot be
recovered during import or refresh. `ttl` is also not reconstructed from the
expiration timestamp, so omit it after importing an existing token unless you
intend to replace that token.

## Example Usage

```terraform
resource "motherduck_service_account" "app" {
  username = "analytics_app"
}

resource "motherduck_access_token" "app" {
  username    = motherduck_service_account.app.username
  name        = "terraform-managed"
  description = "Nightly ingestion pipeline"
  token_type  = "read_write"
  ttl         = 2592000
}
```

## Rotation and state

Use `read_write` for provisioning and ingestion, and `read_scaling` for supported
read-only serving connections. Two tokens for one account do not create separate
data ownership. Read-scaling readers need account initialization and any share
attachment through a read-write connection first. MotherDuck creates
`read_scaling` tokens only for organizations on a Business plan or an active
free trial, unless it has enabled read scaling for the organization.

MotherDuck creates tokens only for your own user or for a service account. A
token for another human user fails.

Token names must be unique among a user's unexpired tokens, and MotherDuck
rejects a duplicate with a 409 conflict. A replacement that reuses the name
therefore fails under `create_before_destroy`, because the new token is created
while the old one still exists. Give each token generation a distinct name,
for example with a rotation suffix.

Token name, type, and TTL changes require replacement. A username change also
requires replacement unless only its letter case changes, because MotherDuck
compares usernames case-insensitively. MotherDuck
cannot edit a token description, so changing a configured `description` also
replaces the token. Omitting `description` keeps whatever MotherDuck reports,
including a description set outside Terraform. The names `MotherDuck Extension`
and `MotherDuck Flights` are reserved for tokens MotherDuck creates itself.
Destroy revokes the token. TTL is not a rotation schedule. To avoid interrupting consumers,
create a second token, update and verify consumers, then retire the old one.

The generated secret is stored in Terraform state. A sensitive output masks
normal CLI display but does not encrypt state. If a token disappears from the
API listing, refresh removes its state so the next apply can create a new one.
The provider warns when it cannot explain the absence by the recorded expiry.
The listing, and the `motherduck_user_tokens` data source, include only
unexpired tokens.

See [authentication and rotation](../guides/authentication.md) and
[reader setup](../guides/sharing-and-read-scaling.md).

## Import

```shell
terraform import motherduck_access_token.app 'analytics_app/<token_id>'
```

The token ID must be the UUID MotherDuck reports, for example from
`motherduck_user_tokens`. A token name is not accepted.

After import, run `terraform plan` with the token's name and type. Keep `ttl`
omitted to adopt an existing token without requesting replacement. Import reads
the description back, so either omit `description` or set it to the value
MotherDuck reports. Terraform
cannot recover the original lifetime or token secret.

## Schema

### Required

- `name` (String) Access token label. Must be non-blank and 1-255 characters, counted in UTF-16 code units. It must be unique among the user's unexpired tokens. `MotherDuck Extension` and `MotherDuck Flights` are reserved.
- `username` (String) Your own username or a service account username. MotherDuck refuses tokens for other human users. Must be non-blank and 1-255 characters. MotherDuck compares usernames case-insensitively, so a change in letter case updates the resource in place. Any other change replaces the token.

### Optional

- `description` (String) Optional free-form notes on the token's purpose. Must be non-blank and 1-1000 characters. MotherDuck cannot edit a description, so changing a configured value replaces the token. When omitted, Terraform keeps whatever description MotherDuck reports, including one set outside Terraform.
- `token_type` (String) `read_write` or `read_scaling`. Defaults to `read_write`. Changing this value replaces the token.
- `ttl` (Number) Optional token lifetime in seconds. Must be between 300 and 31536000. Changing this value replaces the token.

### Read-Only

- `created_ts` (String) Token creation timestamp reported by MotherDuck.
- `expire_at` (String) Token expiration timestamp reported by MotherDuck.
- `id` (String) Access token ID assigned by MotherDuck.
- `read_only` (Boolean) Whether the token is read-only according to MotherDuck.
- `token` (String, Sensitive) Token secret, returned only at creation time.
