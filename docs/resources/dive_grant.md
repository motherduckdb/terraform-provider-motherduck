# motherduck_dive_grant (Resource)

Grants `read` on one MotherDuck Dive to a user, a role, or the whole organization. The grantee can then open the Dive. Reading the data behind it still needs access to the databases and shares the Dive queries.

Use this resource when Terraform owns who can open a Dive. Each resource owns
one grant: to one user or service account, to one role, or to the whole
organization. The owner of a Dive and organization admins can grant and revoke
access to it, so configure the provider `token` (or `MOTHERDUCK_TOKEN`) with
one of those principals. To any other principal MotherDuck reports the Dive as
not found.

During refresh, the provider reads the grants from `MD_LIST_DIVE_GRANTEES`. If
the grant is revoked outside Terraform, the next plan recreates it. If the Dive
is deleted, the grant is removed from state. MotherDuck resolves principal
names case-insensitively, so a change in the letter case of `grantee_name` only
updates state and does not revoke the grant.

## The organization grant on new Dives

MotherDuck can create a Dive with a `read` grant for the whole organization
already in place. Whether it does depends on the organization. Read
[motherduck_dive_grantees](../data-sources/dive_grantees.md) to see the grants
a Dive has.

- To keep a Dive readable by the whole organization, declare a grant with
  `grantee_type = "organization"`. Granting again is harmless when the grant
  already exists.
- To make a Dive private, import the existing organization grant as
  `<dive_id>/organization`, then remove the resource from the configuration.
  The next apply revokes it. Destroying an organization grant always revokes
  it, including one that MotherDuck created with the Dive.

## Embedding

[motherduck_dive_embed_session](../ephemeral-resources/dive_embed_session.md)
needs a service account that can read the Dive. Grant `read` to that service
account, or to a role it holds, instead of relying on the organization grant.
A read grant opens the Dive only. The data it shows still depends on the
databases and shares the reader can query.

## Example Usage

```terraform
resource "motherduck_dive" "revenue" {
  title   = "Revenue"
  content = <<-JSX
    export default function Dive() {
      return <h1>Revenue</h1>
    }
  JSX
}

resource "motherduck_role" "finance" {
  name = "finance"
}

# Let every member of the finance role open the Dive.
resource "motherduck_dive_grant" "finance" {
  dive_id      = motherduck_dive.revenue.id
  grantee_type = "role"
  grantee_name = motherduck_role.finance.name
}

# Let the service account that creates embed sessions read the Dive.
resource "motherduck_dive_grant" "embed" {
  dive_id      = motherduck_dive.revenue.id
  grantee_name = "embed_service"
}
```

## Schema

### Required

- `dive_id` (String) ID of the Dive to grant `read` on. Must be a UUID. Changing it replaces the grant.

### Optional

- `grantee_name` (String) User, service account, or role that receives the grant. Required unless `grantee_type` is `organization`, and must be omitted for the organization grant. Must be non-blank and must not include leading or trailing whitespace. MotherDuck resolves principals case-insensitively, so changing only the letter case updates state in place instead of revoking and granting the same principal.
- `grantee_type` (String) Principal type: `user`, `role`, or `organization`. Defaults to `user`. `organization` grants to every member of the organization. Changing it replaces the grant.

### Read-Only

- `id` (String) Grant ID in `<dive_id>/<grantee_type>/<grantee_name>` form, or `<dive_id>/organization` for the organization grant.

## Import

Import a grant with `<dive_id>/<grantee_type>/<grantee_name>`, or with
`<dive_id>/organization` for the organization grant:

```shell
terraform import motherduck_dive_grant.finance 123e4567-e89b-42d3-a456-426614174000/role/finance
terraform import motherduck_dive_grant.everyone 123e4567-e89b-42d3-a456-426614174000/organization
```
