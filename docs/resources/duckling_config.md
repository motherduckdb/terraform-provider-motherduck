# motherduck_duckling_config (Resource)

Configure read-write and read-scaling compute for an existing user or service
account. This resource uses the organization admin credential.

## Sizing the workload

The settings apply to the named account. To scale a separate BI reader,
configure that reader's username, not the writer's. A read-scaling pool limit is
not a preallocated count of continuously running replicas.

Instance-size and pool changes update the configuration in place. A username
change replaces the resource unless only its letter case changes, because
MotherDuck compares usernames case-insensitively. Pulse does not accept
cooldown settings, so omit the corresponding cooldown when selecting Pulse.

Cooldowns are optional. MotherDuck stores the configuration exactly as written,
so a write without a cooldown resets it. On create, Terraform sends no cooldown
for an unset one, so MotherDuck applies its default and replaces any cooldown
set outside Terraform, such as in the MotherDuck UI. To keep such a cooldown,
set it in the configuration before the first apply, or import the resource.
After that, Terraform records the live value of an unset cooldown and keeps it
while that instance size stays the same. When the instance size changes,
MotherDuck applies its default for the new size. Removing a configured cooldown
keeps the current value, so set the value you want instead of deleting the
line.

An unset cooldown on a Pulse size is always cleared. When a plan limit lowers
an account to Pulse, MotherDuck keeps reporting the cooldown stored for the
larger size, but it rejects any cooldown in a write for Pulse. Terraform plans
no cooldown for Pulse and sends none.

Measure representative queries and concurrency before choosing production
sizes. The provider validates accepted values, while the service enforces
availability and account-specific limits.

## Plan limits

MotherDuck rejects a configuration above the limits of the organization's plan.
The provider then names the plan and its default limits in the error. These
are the default limits:

| Plan | Read-write size | Read-scaling size | Flock size |
| --- | --- | --- | --- |
| Free | `pulse` | `pulse` | at most 4 |
| Lite | `pulse` | `pulse` | 0 |
| Trial not yet started | up to `jumbo` | up to `jumbo` | at most 4 |
| Active free trial | up to `mega` | up to `jumbo` | at most 16 |
| Business | up to `giga` | up to `jumbo` | at most 16 |

MotherDuck can set different limits for an organization or a single user, so
the provider does not check these values itself.

## Destroy and import

Destroy removes this resource from Terraform state **without resetting the live
compute settings**, because the API has no reset/delete operation for them.
The provider emits a warning. Change the configuration explicitly when you want
to resize compute before giving up management.

Import by username. See [read scaling](../guides/sharing-and-read-scaling.md).

## Example Usage

```terraform
resource "motherduck_duckling_config" "app" {
  username = motherduck_service_account.app.username

  read_write_instance_size      = "standard"
  read_write_cooldown_seconds   = 600
  read_scaling_instance_size    = "standard"
  read_scaling_flock_size       = 2
  read_scaling_cooldown_seconds = 600
}

resource "motherduck_service_account" "app" {
  username = "analytics_app"
}
```
