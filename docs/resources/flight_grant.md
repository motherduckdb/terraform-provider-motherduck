# motherduck_flight_grant (Resource)

Grants `run` on one MotherDuck Flight to a user, a role, or the whole organization. The grantee can then start runs of the Flight. Runs use the access token and secrets of the Flight owner, and a run grant does not let the grantee see or edit the Flight.

Use this resource when Terraform owns who can run a Flight besides its owner.
Each resource owns one grant: to one user or service account, to one role, or
to the whole organization. Only the owner of a Flight can grant access to it,
so configure the provider `token` (or `MOTHERDUCK_TOKEN`) with the owner's
token. Organization admins can revoke grants on other users' Flights but cannot
add them.

A new Flight has no grants, so only its owner can run it. A run started through
a grant uses the access token and secrets of the Flight owner. The grant does
not let the grantee see, edit, or delete the Flight, and MotherDuck reports the
Flight as not found to a grantee who cannot otherwise see it. See
[motherduck_flight_run](flight_run.md#access-to-the-flight) for how a run
started by such a principal behaves in Terraform.

During refresh, the provider reads the grants from `MD_LIST_FLIGHT_GRANTEES`.
If the grant is revoked outside Terraform, the next plan recreates it. If the
Flight is deleted, the grant is removed from state. MotherDuck resolves
principal names case-insensitively, so a change in the letter case of
`grantee_name` only updates state and does not revoke the grant.

To review everyone who can run a Flight, read
[motherduck_flight_grantees](../data-sources/flight_grantees.md).

## Example Usage

```terraform
resource "motherduck_flight" "refresh_crm" {
  name            = "refresh_crm"
  max_runtime_sec = 900

  source_code = <<-PY
    def main():
        print("refreshing")

    if __name__ == "__main__":
        main()
  PY
}

resource "motherduck_role" "operators" {
  name = "operators"
}

# Let every member of the operators role start runs of the Flight.
resource "motherduck_flight_grant" "operators" {
  flight_id    = motherduck_flight.refresh_crm.id
  grantee_type = "role"
  grantee_name = motherduck_role.operators.name
}
```

## Schema

### Required

- `flight_id` (String) ID of the Flight to grant `run` on. Must be a UUID. Changing it replaces the grant.

### Optional

- `grantee_name` (String) User, service account, or role that receives the grant. Required unless `grantee_type` is `organization`, and must be omitted for the organization grant. Must be non-blank and must not include leading or trailing whitespace. MotherDuck resolves principals case-insensitively, so changing only the letter case updates state in place instead of revoking and granting the same principal.
- `grantee_type` (String) Principal type: `user`, `role`, or `organization`. Defaults to `user`. `organization` grants to every member of the organization. Changing it replaces the grant.

### Read-Only

- `id` (String) Grant ID in `<flight_id>/<grantee_type>/<grantee_name>` form, or `<flight_id>/organization` for the organization grant.

## Import

Import a grant with `<flight_id>/<grantee_type>/<grantee_name>`, or with
`<flight_id>/organization` for the organization grant:

```shell
terraform import motherduck_flight_grant.operators 123e4567-e89b-42d3-a456-426614174000/role/operators
terraform import motherduck_flight_grant.everyone 123e4567-e89b-42d3-a456-426614174000/organization
```
