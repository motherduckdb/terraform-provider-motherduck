## Highlights

- The examples are version-pinned, rotate tokens more safely and provide complete Terraform root modules that can be copied as they are. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.12...v0.2.13)

## Upgrading from v0.2.12

Version constraints such as `~> 0.2.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it.
3. Update module sources that reference `?ref=v0.2.12`.
4. Configurations based on the writer, reader or tenant blueprints should review the token retirement change under [Compatibility](#compatibility).

## Bug Fixes

- The blueprints now refuse to retire a legacy writer or reader token unless the named replacement token already exists. Operators must still confirm that consumers use the replacement before retiring the previous token. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.12...v0.2.13)
- The blueprint root modules expose, as sensitive outputs, the rotation tokens, reader setup tokens and share URLs that later steps require. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.12...v0.2.13)

## Compatibility

- Provider schemas, import formats and supported Terraform versions are unchanged. Token retirement in the three blueprints now requires a prior rotation apply and an admin token that can list the tokens of the account. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.12...v0.2.13)

## Maintenance

- The cookbook pipeline example warns that changing its database name replaces the database and deletes the tables that its runtime created. The Registry guides link to the v0.2.13 examples. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.12...v0.2.13)
