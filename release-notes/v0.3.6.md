## Highlights

- Access token refresh keeps the existing token in state when the REST API returns an empty or null response body. Terraform reports a read error instead of proposing another token. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.5...v0.3.6)

## Bug Fixes

- REST operations that require a response object reject empty and JSON `null` bodies. Previously, these responses could look like an empty token inventory, removing a live token from state and causing the next apply to create another token. Explicit empty inventories and successful no-content deletes still work. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.5...v0.3.6)

## Upgrading

Run `terraform init -upgrade` and review `terraform plan`. Constraints such as `~> 0.3.0` select this version. If an earlier refresh already removed a live token from state, import it with `<username>/<token_id>` before applying. Import restores management but cannot recover the one-time token secret.

## Compatibility

- Resource schemas, import formats and the provider source address are unchanged. Missing response objects now fail refresh instead of being accepted as empty results. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.5...v0.3.6)
