## Highlights

- Access token refresh keeps the existing token in state when the MotherDuck REST API returns an empty or null response body. Terraform reports a read error instead of planning a replacement token. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.5...v0.3.6)

## Upgrading from v0.3.5

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it.
3. If an earlier refresh removed a live access token from state, import it with the ID `<username>/<token_id>` before applying. Import restores management of the token but cannot recover its one-time secret.
4. Update pinned refs and module sources that reference `v0.3.5`.

## Bug Fixes

- REST operations that require a response object now reject empty and JSON `null` response bodies. Previously, such a response could be read as an empty token inventory, which removed a live token from state and caused the next apply to create another token. Explicitly empty inventories and successful deletions without content are still accepted. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.5...v0.3.6)

## Compatibility

- Resource schemas, import formats and the provider source address are unchanged. A missing response object now fails the refresh instead of being treated as an empty result. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.5...v0.3.6)
