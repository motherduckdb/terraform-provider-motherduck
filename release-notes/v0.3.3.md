## Highlights

- List the users and service accounts in your organization with the new `data.motherduck_users`, backed by the `GET /v1/users` endpoint that MotherDuck released to production on 2026-10-07. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)

## Upgrading from v0.3.2

Constraints such as `~> 0.3.0` already select v0.3.3.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review it before applying. This release adds a data source and changes no existing schema, so existing configurations plan no changes.

## Features

- `data.motherduck_users` lists the users and service accounts in the organization of the admin token. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)
  - Set `is_service_account` to list only service accounts or only human users, and `is_deprovisioned` to list only deprovisioned or only active users. Omit either to list both.
  - Each entry has `id`, `username`, `email`, `first_name`, `last_name`, `is_service_account`, `is_deprovisioned`, and the names of the roles granted directly to the user in `roles`.
  - The provider reads every page and returns users sorted by username, so the list does not depend on page size.
  - The admin token needs the `member_management.view_all_members` privilege, which the built-in `admin`, `builder` and `explorer` roles include.

## Compatibility

- Existing resource schemas, import formats and the provider source address are unchanged. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)

## Maintenance

- The provider now continues paged REST listings with `page_token`, the convention `GET /v1/users` set for MotherDuck's public API. Access token and active account listings return a single page today, so their requests are unchanged in effect. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)
