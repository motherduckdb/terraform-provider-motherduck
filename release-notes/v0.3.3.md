## Highlights

- The new `motherduck_users` data source lists the users and service accounts of an organization. It uses the `GET /v1/users` endpoint that MotherDuck released on 2026-10-07. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)

## Upgrading from v0.3.2

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. This release adds a data source and changes no existing schema, so existing configurations plan no changes.
3. Update pinned refs and module sources that reference `v0.3.2`.

## Features

- The `motherduck_users` data source lists the users and service accounts in the organization of the admin token. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)
  - `is_service_account` restricts the list to service accounts or to human users, and `is_deprovisioned` restricts it to deprovisioned or to active users. When an argument is omitted, both kinds are listed.
  - Each entry has `id`, `username`, `email`, `first_name`, `last_name`, `is_service_account`, `is_deprovisioned`, and `roles`, which holds the names of the roles granted directly to the user.
  - The provider reads every page and sorts users by username, so the result does not depend on page size.
  - The admin token requires the `member_management.view_all_members` privilege, which the built-in `admin`, `builder` and `explorer` roles include.

## Compatibility

- Existing resource schemas, import formats and the provider source address are unchanged. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)

## Maintenance

- The provider continues paged REST listings with `page_token`, the pagination convention of the MotherDuck public API. Access token and active account listings currently return a single page, so their requests are unchanged in effect. [#75](https://github.com/motherduckdb/terraform-provider-motherduck/pull/75)
