## Highlights

- The provider now manages row-level security, column-level security and column masking on shares. The new `motherduck_share_secure_view` resource filters rows, hides columns and masks values for each consumer of a share, and `motherduck_share_secure_views` lists every secure view on a share for audits. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)
- Share and role grants now plan a replacement when `grantee_type` changes, and catalog lookups by name ignore letter case in every data source, as the resources already did. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- A new guide, [Secure shared rows and columns](https://registry.terraform.io/providers/motherduckdb/motherduck/latest/docs/guides/row-and-column-security), covers fail-closed shares, which workflow owns each policy, a pooled multi-tenant design, and how to migrate Snowflake or Databricks policies. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)

## Upgrading from v0.3.8

Version constraints such as `~> 0.3.0` select this release. It adds a resource and a data source, fixes several defects, and tightens some validation.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review it before applying. Configurations that previously failed to apply a `grantee_type` change now plan a replacement of that grant. Other existing resources are not expected to change.
3. Update pinned refs and module sources that reference `v0.3.8`.

Review these changes before upgrading. The [Compatibility](#compatibility) section describes each one.

- Plan-time rejection of blank data source names and of control characters in `custom_user_agent`.
- Empty `token`, `admin_token` and `api_base_url` provider arguments now fall back to their environment variables.
- Case-insensitive name matching in catalog data sources.

Secure views require a Business or Enterprise plan, or an active free trial, and must be managed with a read-write token of the share owner.

## Features

- `motherduck_share_secure_view` manages one secure view on a share:
  - Changing `query` updates the secure view in place with `ADD OR REPLACE`, so consumers never see the source table without a policy during the change.
  - Creating a secure view that already exists on the share fails with its import ID instead of overwriting it.
  - Changes to the stored body made outside Terraform plan an update. Surrounding whitespace, such as the trailing newline of a heredoc, is ignored on refresh.
  - A secure view whose share was dropped or replaced is removed from state. Add `replace_triggered_by = [motherduck_share.<name>.created_ts]` so the same apply recreates it.
  - Import with `<share>.<schema>.<name>`.

  [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)
- `motherduck_share_secure_views` lists the schema, name, body, `replaces_table` flag and columns of every secure view on a share, including views Terraform does not manage. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)

## Bug Fixes

- Removing `grantee_type = "role"` from a `motherduck_share_grant` or `motherduck_role_grant` previously planned an in-place update that failed on every apply. Any change to `grantee_type` now plans a replacement of the grant. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- The `motherduck_database` data source and the `name` or `database_name` filters of `motherduck_databases`, `motherduck_owned_shares`, `motherduck_shared_with_me`, `motherduck_secrets`, `motherduck_database_snapshots` and `motherduck_storage_info` matched names exactly. A name that differed only in letter case returned no rows or failed with "not found". These lookups now ignore letter case, as MotherDuck and the matching resources do. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- `motherduck_shared_with_me` ordered rows by name only, so two shares with the same name from different owners could change places between reads and move between pages. Rows are now ordered by name, owner and URL. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- When a `motherduck_guide` update wrote new content and the following access change failed, state kept the previous content until the next refresh. State now records the content that was written, and invalid references fail before any change is written. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- A `motherduck_table` column type that referenced another resource failed validation with an error that described a provider defect. The type is now validated once it is known, and the plan replaces the table. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- `motherduck_active_accounts` now orders `accounts_json` like the typed `accounts` list, so a change in server order no longer changes the value. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- `motherduck_dive` and `motherduck_flight` no longer leave `current_version` unknown when MotherDuck does not report a version. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- Snapshot creation errors for a name that already exists now include the import ID, as the other SQL resources do, and the Flight `instance_type` error no longer suggests `F8`, which no plan offers. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)

## Compatibility

- The provider treats an empty or whitespace-only `token`, `admin_token` or `api_base_url` argument as unset and uses `MOTHERDUCK_TOKEN`, `MOTHERDUCK_ADMIN_TOKEN` or `MOTHERDUCK_API_BASE_URL` instead. Configurations that relied on an empty argument to ignore those variables should unset the variables. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- `custom_user_agent` rejects control characters, such as a newline or tab inside the value, at plan time. Previously every REST request failed. Leading and trailing whitespace is still trimmed. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- The `motherduck_database` and `motherduck_secret` data sources reject a blank `name` at plan time. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- Catalog data sources that filter by name now return objects whose names differ from the configured value only in letter case. Configurations that relied on an exact-case mismatch to return no rows should review those filters. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
- Import IDs for usernames are limited to 255 UTF-16 code units, the limit that configuration validation already applied. [#106](https://github.com/motherduckdb/terraform-provider-motherduck/pull/106)
