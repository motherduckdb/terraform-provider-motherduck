## Highlights

- Manage row-level security, column-level security and column masking on shares. The new `motherduck_share_secure_view` resource filters rows, hides columns and masks values for each consumer of a share, and `motherduck_share_secure_views` lists every secure view on a share for audits. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)
- A new guide, [Secure shared rows and columns](https://registry.terraform.io/providers/motherduckdb/motherduck/latest/docs/guides/row-and-column-security), covers fail-closed shares, which workflow owns each policy, a pooled multi-tenant design, and how to move from Snowflake or Databricks policies. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)

## Upgrading from v0.3.8

Version constraints such as `~> 0.3.0` select this release. It adds a resource and a data source and does not change existing ones.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and confirm that it proposes no changes to existing resources.
3. Secure views need a Business or Enterprise plan, or an active free trial. Manage them with the share owner's read-write token.

## Features

- `motherduck_share_secure_view` manages one secure view on a share:
  - Changing `query` updates the secure view in place with `ADD OR REPLACE`, so consumers never see the source table without a policy during the change.
  - Creating a secure view that already exists on the share fails with its import ID instead of overwriting it.
  - Changes to the stored body made outside Terraform plan an update. Surrounding whitespace, such as the trailing newline of a heredoc, is ignored on refresh.
  - A secure view whose share was dropped or replaced is removed from state. Add `replace_triggered_by = [motherduck_share.<name>.created_ts]` so the same apply recreates it.
  - Import with `<share>.<schema>.<name>`.

  [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)
- `motherduck_share_secure_views` lists the schema, name, body, `replaces_table` flag and columns of every secure view on a share, including views Terraform does not manage. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)

## Documentation

- The customer-facing analytics guide compares a database per tenant with a pooled table protected by secure views. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)
- The share and access control pages now state that MotherDuck-hosted DuckLake databases support filtered shares. DuckLake databases with their own data path and Iceberg databases do not. [#98](https://github.com/motherduckdb/terraform-provider-motherduck/pull/98)
- The role grant page and the row and column security guide note that role grants and revokes take up to about a minute to reach `is_role_in_session()`, so a revoked role can unmask a column briefly. [#99](https://github.com/motherduckdb/terraform-provider-motherduck/pull/99)
