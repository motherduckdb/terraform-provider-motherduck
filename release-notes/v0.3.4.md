## Highlights

- Terraform can now refresh and destroy a retained snapshot whose creating database was dropped before Terraform saved the snapshot ID. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.3...v0.3.4)
- Provider binaries are built with Go 1.27.2 and `golang.org/x/net` 0.60.0, which fix reachable HTTP, HTTP/2 and TLS vulnerabilities. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.3...v0.3.4)

## Upgrading from v0.3.3

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. A retained snapshot without an ID now refreshes successfully after its creating database was dropped.
3. Destroy the snapshot when it is no longer needed. The cleanup requires another native MotherDuck database in the account.
4. Update pinned refs and module sources that reference `v0.3.3`.

## Bug Fixes

- A snapshot create can succeed before the catalog read that follows it fails, which leaves Terraform with the database and name of the snapshot but no ID. Previously, refresh and destroy stopped when the database could not be attached. They now recover the unique ID from the snapshot catalog once the database is confirmed missing. Refresh keeps the snapshot in state with a warning, and destroy clears its name from another native database. Permission failures, unavailable metadata and ambiguous identities still stop the cleanup. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.3...v0.3.4)

## Compatibility

- Resource schemas, import formats and the provider source address `registry.terraform.io/motherduckdb/motherduck` are unchanged. Destroy clears the managed snapshot name and does not guarantee immediate physical deletion. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.3...v0.3.4)
