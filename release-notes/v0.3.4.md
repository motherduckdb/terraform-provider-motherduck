## Highlights

- Recover and release a retained snapshot even when its creating database was dropped before Terraform saved the snapshot ID. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.3...v0.3.4)

## Bug Fixes

- A snapshot create can succeed before catalog readback fails, leaving Terraform with its database and name but no ID. Refresh and destroy now recover the unique ID from the snapshot catalog after a confirmed missing database, instead of stopping at the failed database attachment. Refresh retains the snapshot with a warning. Destroy clears its name from another native database. Permission failures, unavailable metadata and ambiguous identities still stop cleanup. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.3...v0.3.4)

## Maintenance

- Pulumi examples, live programs and the installation guide now pin the published v0.3.3 provider as their baseline. [#76](https://github.com/motherduckdb/terraform-provider-motherduck/pull/76)

## Compatibility

- Public schemas, import formats and `registry.terraform.io/motherduckdb/motherduck` are unchanged. Destroy clears the managed snapshot name and does not promise immediate physical deletion. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.3...v0.3.4)

## Upgrading

Constraints such as `~> 0.3.0` select this maintenance release.

1. Run `terraform init -upgrade`.
2. Review `terraform plan`. A retained snapshot with a missing ID can now refresh successfully after its creating database was dropped.
3. Destroy the snapshot when it is no longer needed. Cleanup requires another native MotherDuck database in the account.
