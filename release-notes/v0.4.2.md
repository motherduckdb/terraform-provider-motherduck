## Highlights

- The provider supports MotherDuck organizations in the Azure regions UK South and East US. The default `api_base_url` routes each request to the region of the token's organization, so Azure organizations need no additional configuration. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)
- `motherduck_agent_usage` reads the updated agent usage schema that MotherDuck introduced in its November 18, 2026 release, and reports the start and end time of each agent run. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)

## Upgrading from v0.4.1

Version constraints such as `~> 0.4.0` select this release. Configurations that read `motherduck_agent_usage` should upgrade before MotherDuck serves the updated agent usage schema to their client, because earlier versions of the provider fail to read it.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. Existing resources are not expected to change.
3. Replace references to `rows[*].run_finished_ts` of `motherduck_agent_usage` with `rows[*].end_time`. See [Compatibility](#compatibility).
4. Update pinned refs and module sources that reference `v0.4.1`.

## Features

- `motherduck_agent_usage` rows have two new attributes. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)
  - `start_time` is the start of the first billed step of the run, excluding agent setup time. It is null when the connected MotherDuck client reports only the finish time.
  - `end_time` is the end of the last billed step of the run, which is when the run finished.
- The documentation covers Azure organizations. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)
  - The provider overview states that the provider works in AWS and Azure regions with the default `api_base_url`.
  - The `motherduck_secret` page includes an `azure` secret for Azure Blob Storage, with a connection string and an `azure://` scope, and lists the `credential_chain` and `service_principal` providers.
  - The customer-facing analytics example lists the regional Postgres hosts, including `pg.uksouth-azure.motherduck.com` and `pg.eastus-azure.motherduck.com`.

## Bug Fixes

- `motherduck_agent_usage` reads agent usage with MotherDuck clients that report the updated schema. With such clients, earlier versions of the data source fail with a binder error, because they filter and sort on `run_finished_ts`, which the updated schema no longer contains. The data source now selects the finish time from whichever column the client reports. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)

## Compatibility

- The `run_finished_ts` attribute of `motherduck_agent_usage` rows is deprecated. It holds the same value as `end_time` with both the current and the earlier schema. Configurations should read `end_time` instead. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)
- With the updated schema, `ai_units` is reported with nine decimal places, for example `1.250000000` instead of `1.25`. Configurations that compare the string value should convert it with `tonumber()`. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)
- MotherDuck now creates new Dives readable by their owner only, unless an organization is exempt. Service accounts that read or embed a new Dive need a `motherduck_dive_grant`. The `motherduck_dive` and `motherduck_dive_grant` pages describe this behavior. [#133](https://github.com/motherduckdb/terraform-provider-motherduck/pull/133)
