## Highlights

- The new `motherduck_compute_usage` data source reads Duckling compute usage for the organization from `MD_INFORMATION_SCHEMA.COMPUTE_USAGE`, in 30-second windows, with filters by user and time window. [#111](https://github.com/motherduckdb/terraform-provider-motherduck/pull/111)
- `motherduck_flight` rejects `MOTHERDUCK_HOST` as a `config` key at plan time, because MotherDuck now sets it for every Flight run and rejects it as a configuration key. [#111](https://github.com/motherduckdb/terraform-provider-motherduck/pull/111)

## Upgrading from v0.3.10

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. Existing resources are not expected to change. A `motherduck_flight` that sets `config.MOTHERDUCK_HOST` now fails at plan time. See [Compatibility](#compatibility).
3. Update pinned refs and module sources that reference `v0.3.10`.

## Features

- New `motherduck_compute_usage` data source. [#111](https://github.com/motherduckdb/terraform-provider-motherduck/pull/111)
  - Each row covers one Duckling for one user in one 30-second window and reports the start and end of the window, the user, the Duckling size and ID, whether the Duckling is a read-scaling replica, the billable uptime, the size multiplier and the query count.
  - `username` filters rows by user name and ignores letter case. `start_time` and `end_time` take RFC 3339 timestamps with a time zone offset and bound the window. The provider sends them in UTC, so the session time zone does not change the window. An `end_time` that is not later than `start_time` fails at plan time.
  - `limit` and `offset` page through rows sorted by window start, user name and Duckling ID.
  - Reading compute usage requires a Business plan and query history access, which organization admins have. A permission or plan error is reported as "MotherDuck query history access required" with the steps to resolve it.
  - The data source requires a MotherDuck client that exposes `md_compute_usage`. When the connected client does not expose it, the read fails with "MotherDuck SQL function unavailable" instead of returning no rows.

## Compatibility

- MotherDuck now sets `MOTHERDUCK_HOST` to the API host of the region in which a Flight run executes, and it rejects `MOTHERDUCK_HOST` as a Flight configuration key. [#111](https://github.com/motherduckdb/terraform-provider-motherduck/pull/111)
  - `motherduck_flight` rejects `config.MOTHERDUCK_HOST` at plan time, as it already does for the other reserved names. Remove the key from the configuration. MotherDuck already overrides its value on every run.
  - A `flights` secret with a `MOTHERDUCK_HOST` key in `flight_params` produces a warning, because a Flight run receives that value only as `<secret name>_MOTHERDUCK_HOST`.
  - The reserved key error now states that MotherDuck sets the key for every run.
- MotherDuck now returns the most recent 100 lines of a Flight run log when no `limit` is set, instead of 1,000 lines. `motherduck_flight_logs` without `limit` therefore returns at most 100 rows, and an `offset` without `limit` skips lines within those 100. Set `limit` to read more of a long log. [#111](https://github.com/motherduckdb/terraform-provider-motherduck/pull/111)
- MotherDuck now rejects a Dive embed session with a 403 error when the service account cannot read the Dive. The `motherduck_dive_embed_session` ephemeral resource and data source report that error unchanged. Share the Dive with the service account, or with a role it belongs to, before creating a session. [#111](https://github.com/motherduckdb/terraform-provider-motherduck/pull/111)
- Resource schemas, import formats and the provider source address are unchanged.

## Maintenance

- Documentation updates: [#111](https://github.com/motherduckdb/terraform-provider-motherduck/pull/111)
  - The row and column security guide states that a share holds at most 1,000 secure views, that MotherDuck binds a secure view body with default settings and the UTC time zone instead of the consumer's session settings, and that functions such as `current_date` cannot be used inside a lambda in a secure view body.
  - The `motherduck_flight` documentation lists `MOTHERDUCK_HOST` among the reserved configuration keys and states that no plan currently offers the `F8` instance size.
  - The `motherduck_dive_embed_session` documentation states that the service account must be able to read the Dive.
