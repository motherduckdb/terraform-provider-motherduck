## Highlights

- `motherduck_service_account` only manages service accounts. Before, importing a human user's username and then destroying the resource deleted that user and their data, and deleting the last human user removes the organization. Refresh, import and destroy now look the username up and refuse human users. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- The provider covers more of what MotherDuck exposes in production today: three new data sources, typed rows for Dive, Flight and Guide data sources, organization details on `motherduck_current_user`, and Flight run timing. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Several refresh and plan issues are fixed, among them `motherduck_shared_with_me` source databases, case-only username changes that replaced service accounts, and Flight runs started by a run grant. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)

## Upgrading

Constraints such as `~> 0.3.0` select this version.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review it before applying.
3. Check the items listed under [Compatibility](#compatibility), in particular if you manage service accounts, read `motherduck_shared_with_me.rows[*].source_database`, page through `motherduck_files`, or set an empty Dive `description`.
4. Update pinned refs or module sources that reference `v0.3.7`.

## Features

- New data sources:
  - `motherduck_share` describes one share by `name` (shares you own) or `url` (any share you can see), including its source database and UUID.
  - `motherduck_current_user_tokens` lists the access tokens of the current SQL principal without token IDs.
  - `motherduck_storage_info` reports active, historical, clone-retained and failsafe bytes per database, with optional history. It needs organization-wide storage permission.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Data source additions:
  - `motherduck_current_user` adds `user_id`, `username`, `org_id`, `org_name`, `org_type` and `region`.
  - `motherduck_version` adds `extension_hash`.
  - `motherduck_dive`, `motherduck_dives`, `motherduck_dive_versions`, `motherduck_flight`, `motherduck_flight_versions`, `motherduck_flight_runs`, `motherduck_guide`, `motherduck_guide_versions`, `motherduck_attached_databases`, `motherduck_files` and `motherduck_buckets_for_secret` return typed `rows` next to `rows_json`, so you no longer need `jsondecode`. Content, source code, configuration and URLs stay sensitive.
  - `motherduck_shared_with_me` adds `access`, `visibility`, `update_mode` and `updated_ts`.
  - `motherduck_database_snapshots` adds `database_id`, `active_bytes`, `bytes_written`, `bytes_deleted`, `user_name` and `user_id`.
  - `motherduck_owned_share` and `motherduck_owned_shares` add `source_database_uuid`.
  - `motherduck_guide` accepts `version` to read an earlier Guide version. `motherduck_dive_versions` accepts `limit` and `offset`.
  - `motherduck_active_accounts` adds a typed, sensitive `accounts` list.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Resource additions:
  - `motherduck_flight_run` reports `started_at`, `ended_at`, `scheduled_at`, `cancelled_at`, `exit_code` and `is_scheduled`.
  - `motherduck_dive` adds `version_description`, `owner_id`, `version_created_at` and a computed `resource_type` for each `required_resources` mount.
  - `motherduck_database` adds the DuckLake creation option `data_inlining_row_limit`.
  - `motherduck_service_account` adds a create-only `description`.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_files` and `motherduck_buckets_for_secret` pass `limit` to MotherDuck, so a small page no longer lists the whole bucket first. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)

## Bug Fixes

- `motherduck_shared_with_me` always returned a null `source_database`, because MotherDuck does not report the source database of a received share. The attribute is deprecated. Use `motherduck_share` with the share URL instead. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Changing only the letter case of `username` on `motherduck_service_account`, `motherduck_access_token` or `motherduck_duckling_config` planned a replacement, which deletes the service account and its data. MotherDuck usernames are case-insensitive, so these changes now update in place. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- A `motherduck_flight_run` started through a run grant on a Flight the principal cannot see was removed from state on refresh, and the next apply started another production run. The run now stays in state with a warning, and `wait_for_status` stops waiting with a warning instead of timing out and tainting the run. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Setting a Dive `description = ""` failed after apply with an inconsistent result, because MotherDuck ignores empty descriptions. The plan now rejects it with an explanation. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_flight_versions` now lists the newest version first, as documented. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- A Duckling configuration above the organization's plan limits failed with `[object Object]` in the error. The provider now names the plan and its default limits. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)

## Compatibility

- `motherduck_service_account` refresh, import and destroy read `GET /v1/users`, which needs the `member_management.view_all_members` privilege. The built-in admin, builder and explorer roles include it. A username that belongs to a human user now fails with an error instead of being managed. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Validation now matches MotherDuck:
  - Usernames may start with any Unicode letter, and lengths count UTF-16 code units, as the server does.
  - `motherduck_access_token` import requires the token ID to be a UUID.
  - `required_resources` URLs on `motherduck_dive` must start with `md:`.
  - `motherduck_dive_versions` paging values are capped at 4294967295.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_files` pages now follow object key order, where a folder sorts as its name followed by a slash. Pages only differ from before when a folder and a file share a name prefix at a page boundary. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_dive` rejects an empty or removed `description` once one is set, because MotherDuck cannot clear it. Replace the Dive to remove a description. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `data_inlining_row_limit` can only be set when a DuckLake database is created. Changing a recorded value replaces the database. Adding it to an existing database only records the value and does not change the database. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_shared_with_me.rows[*].source_database` is deprecated and will be removed in a future minor release. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
