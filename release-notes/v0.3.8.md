## Highlights

- `motherduck_service_account` now manages service accounts only. In earlier releases, importing the username of a human user and then destroying the resource deleted that user and the data the user owned. Refresh, import and destroy now verify the account type and refuse human users. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Identifier names that differ only in letter case no longer cause replacements, lost state or failed applies for databases, schemas, tables, views, shares, snapshots and grants. A case-only rename of a database previously planned to drop and recreate it. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- The provider covers more of the MotherDuck production surface, with three new data sources, typed rows for the Dive, Flight and Guide data sources, organization details on `motherduck_current_user`, and Flight run timing. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)

## Upgrading from v0.3.7

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it.
3. Review the items under [Compatibility](#compatibility). They are most relevant to configurations that manage service accounts, use `wait_for_status` on `motherduck_flight_run`, read `motherduck_shared_with_me.rows[*].source_database` or `motherduck_guides` reference URLs, or page through the Dive, Flight and Guide data sources.
4. Update pinned refs and module sources that reference `v0.3.7`.

## Features

- New data sources:
  - `motherduck_share` describes one share by `name` for owned shares or by `url` for any visible share, including its source database and source database UUID.
  - `motherduck_current_user_tokens` lists the access tokens of the current SQL principal. It does not return token IDs.
  - `motherduck_storage_info` reports active, historical, clone-retained and failsafe bytes per database, with optional history. It requires organization-wide storage permission.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Data source additions:
  - `motherduck_current_user` adds `user_id`, `username`, `org_id`, `org_name`, `org_type` and `region`. `motherduck_version` adds `extension_hash`.
  - `motherduck_dive`, `motherduck_dives`, `motherduck_dive_versions`, `motherduck_flight`, `motherduck_flight_versions`, `motherduck_flight_runs`, `motherduck_guide`, `motherduck_guide_versions`, `motherduck_attached_databases`, `motherduck_files` and `motherduck_buckets_for_secret` return typed `rows` alongside `rows_json`, so configurations no longer need `jsondecode`. Content, source code, configuration and URLs remain sensitive.
  - `motherduck_shared_with_me` adds `access`, `visibility`, `update_mode` and `updated_ts`.
  - `motherduck_database_snapshots` adds `database_id`, `active_bytes`, `bytes_written`, `bytes_deleted`, `user_name` and `user_id`.
  - `motherduck_owned_share` and `motherduck_owned_shares` add `source_database_uuid`.
  - `motherduck_guide` accepts `version` to read an earlier Guide version. `motherduck_dive_versions` accepts `limit` and `offset`.
  - `motherduck_active_accounts` adds a typed, sensitive `accounts` list.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Resource additions:
  - `motherduck_flight_run` reports `started_at`, `ended_at`, `scheduled_at`, `cancelled_at`, `exit_code` and `is_scheduled`.
  - `motherduck_dive` adds `version_description`, `owner_id`, `version_created_at` and a computed `resource_type` for each `required_resources` mount.
  - `motherduck_database` adds the DuckLake creation option `data_inlining_row_limit`.
  - `motherduck_service_account` adds a create-only `description`.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_files` requests only the entries needed for the requested page, so a small page no longer lists the entire storage path first. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)

## Bug Fixes

- Identifier case handling:
  - A `motherduck_snapshot` whose `database` differed in case from the actual database name was created but could not be read, refreshed or destroyed. Snapshot lookups now match database names case-insensitively.
  - A `motherduck_share` whose `source_database` differed in case from the actual database name failed after apply and was replaced on every later plan, which changed its URL each time. The configured spelling is now kept and the share is not replaced.
  - Schemas, tables and views whose `database` or `schema` differed in case from the actual names were removed from state on refresh, and the next apply failed because the objects already existed. These lookups now follow the case rules of MotherDuck and DuckDB.
  - Case-only changes to database, schema, table, view, share and snapshot names, and to share grant and role grant principals, planned a replacement. These changes now update state in place without dropping or recreating objects.
  - Changing only the letter case of `username` on `motherduck_service_account`, `motherduck_access_token` or `motherduck_duckling_config` planned a replacement, which deletes the service account and its data. These changes now update in place.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Flight, Flight run, Dive and Guide resources:
  - Removing `schedule_cron` from a `motherduck_flight` failed on every apply, because MotherDuck keeps the disabled schedule. Switching between `schedule_cron = ""` and an unset value also failed. Both cases now apply cleanly.
  - A `motherduck_flight_run` whose `wait_for_status` timed out or was interrupted was marked for replacement, and the next apply started a second run. The run now remains in state with a warning.
  - A `motherduck_flight_run` started through a run grant on a Flight that the principal cannot see was removed from state on refresh, and the next apply started another run. The run now remains in state with a warning.
  - A `motherduck_dive` whose `status` was rejected during creation was later destroyed and recreated with a new ID. The Dive now remains in place and the status change is retried. A partially failed Dive update no longer causes the same content to be written again as an additional version.
  - Importing a Dive or a Guide whose mount or reference URLs differed in spelling from the form MotherDuck reports wrote an additional version, and for Dives could change `api_version`. Equivalent URLs no longer cause a write.
  - Guide references that MotherDuck reported in a different spelling failed after apply. The configured spelling is now kept.
  - Setting a Dive `description = ""` failed after apply, because MotherDuck ignores empty descriptions. The plan now rejects it with an explanation.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Access tokens, service accounts and Duckling configurations:
  - Removing `token_type` from a `read_scaling` access token, or importing such a token without `token_type`, failed after apply. The attribute now keeps the reported value.
  - Importing an access token with an upper-case token ID failed. Token IDs are now compared without regard to case.
  - After an organization moved to a plan limited to Pulse instances, every change to a `motherduck_duckling_config` failed with a cooldown error, although no cooldown was configured. The provider no longer plans or sends cooldowns for Pulse instances.
  - A Duckling configuration above the plan limits of the organization failed with an unreadable error. The error now names the plan and its default limits.
  - Existing service accounts whose usernames contain `-`, `@` or `.` could not be imported or managed. They are now accepted for existing accounts. New service accounts still follow the current naming rules of MotherDuck.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Secrets, shares and tables:
  - A `motherduck_secret` with a `scope` that MotherDuck renders differently, such as a scope without a URL scheme or with a quote, showed a change on every plan and failed after each apply. The expected scope is now computed the same way MotherDuck renders it.
  - A share `include_pattern` entry with leading or trailing whitespace, or an empty entry, failed after apply. The plan now rejects these entries.
  - A transient error while comparing column types during planning caused a table replacement. The plan now fails with the error instead.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Data sources:
  - `motherduck_shared_with_me` always returned a null `source_database`, because MotherDuck does not report the source database of a received share. The attribute is deprecated in favor of `motherduck_share`.
  - `motherduck_flight_runs` returned incomplete pages when `offset` was set. Pages are now complete.
  - `limit = 0` returned all rows, or an error, for several Dive, Flight and Guide data sources. It now returns no rows.
  - `motherduck_flight_versions` now lists the newest version first, as documented.
  - `motherduck_active_accounts.accounts_json` returned `null` for an organization without active accounts. It now returns an empty list.
  - Share URLs used as `motherduck_guides` reference filters could appear in plan output and error messages. The filter is now sensitive and URLs are redacted from errors.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Diagnostics:
  - A plan that changes resources while the required token is missing now warns that the apply will fail. Previously the missing token was reported only during apply.
  - A rejected or expired SQL or admin token now produces an error that names the provider argument and environment variable to check, instead of the raw gateway message.
  - Creating a database, schema, table, view, share, secret, role or service account that already exists now explains how to import the existing object and gives its import ID.
  - Creating a schema, table, view, share or snapshot in a database that does not exist, or a table or view in a schema that does not exist, now explains that a literal name does not order resource creation and recommends referencing the managed resource.
  - Destroying a schema that still contains other objects now points to `cascade_on_delete`. Destroying a database that still has shares now explains that the shares must be destroyed first.
  - Role and role grant changes refused for lack of privileges now explain that the SQL token, not `admin_token`, must authorize role management.
  - An unknown table column type now names the column and no longer shows the internal query used to check the type.
  - Data source errors now name the data source, for example "Unable to read motherduck_current_user".

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- The REST client no longer follows redirects that downgrade from HTTPS to HTTP or change the host or port, so the administrative token is not sent to another destination. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)

## Compatibility

- `motherduck_service_account` refresh, import and destroy read `GET /v1/users`, which requires the `member_management.view_all_members` privilege. The built-in admin, builder and explorer roles include it. A username that belongs to a human user now fails with an error instead of being managed. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- When `wait_for_status` on `motherduck_flight_run` times out or is interrupted, the apply now succeeds with a warning and `status` holds the last observed value. Configurations that rely on `wait_for_status` to block dependent resources should add a `precondition` on `status` to those resources, as the resource documentation describes. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Validation now matches MotherDuck:
  - Usernames may start with any Unicode letter, and length limits count UTF-16 code units.
  - `motherduck_access_token` import requires the token ID to be a UUID.
  - `required_resources` URLs on `motherduck_dive` must start with `md:`.
  - Share `include_pattern` entries must not be empty or contain leading or trailing whitespace.
  - `limit` and `offset` on the Dive data sources are limited to 2147483647, and on the Flight and Guide data sources to 4294967295.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- Names that MotherDuck refuses are now rejected at plan time instead of during apply:
  - Database and share names must not contain a forward slash and must be at most 254 characters.
  - Secret names must be at most 255 characters.
  - A change to a database name, or to a `database` or `source_database` reference, that only changes the letter case of a non-ASCII character fails at plan time, because MotherDuck cannot attach that spelling. Keep the existing spelling.
  - Schema, table and view names are compared without regard to case only for ASCII letters, as DuckDB does.

  [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `reference_url` on `motherduck_guides` is now sensitive. Outputs that expose it must be marked `sensitive = true`. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `token_type` on `motherduck_access_token` no longer has a static default. New tokens are still created as `read_write` when the attribute is not set. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_files` pages now follow object key order, where a folder sorts as its name followed by a slash. Pages differ from earlier releases only when a folder and a file share a name prefix at a page boundary. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_dive` rejects an empty or removed `description` once a description is set, because MotherDuck cannot clear it. Removing a description requires replacing the Dive. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `data_inlining_row_limit` applies only when a DuckLake database is created. Changing a recorded value replaces the database. Adding the attribute to an existing database records the value without changing the database. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
- `motherduck_shared_with_me.rows[*].source_database` is deprecated and will be removed in a future minor release. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.7...v0.3.8)
