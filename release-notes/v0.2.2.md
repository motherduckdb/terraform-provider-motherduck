## Highlights

- Release checksums now carry a detached GPG signature, which is the last artifact the Terraform Registry requires to ingest a release. [#25](https://github.com/motherduckdb/terraform-provider-motherduck/pull/25)

## Tooling and Release

- `scripts/sign-release.sh` signs the checksum file in an isolated `GNUPGHOME`, asserts the signature is binary rather than ASCII-armored, and verifies it before the release is created. `GPG_FINGERPRINT` pins the expected signer and accepts either a long key ID or a full fingerprint. [#25](https://github.com/motherduckdb/terraform-provider-motherduck/pull/25)
- The release job runs in the protected `motherduck-release` environment, restricted to `v*` tags, and refuses to publish unless the checksums, signature, and protocol manifest are all present. [#25](https://github.com/motherduckdb/terraform-provider-motherduck/pull/25)
- `make release-sign-check` exercises signing with a throwaway key and covers tampered input, a missing key, a wrong passphrase, and a fingerprint mismatch. It runs inside `make static-check` and the release preflight, and requires `gpg`. [#25](https://github.com/motherduckdb/terraform-provider-motherduck/pull/25)

## Compatibility

- No provider runtime or schema changes. This is the first release eligible for Terraform Registry ingestion; v0.1.0 through v0.2.1 are unsigned and cannot be ingested. Installing from GitHub Releases through a filesystem mirror continues to work unchanged. [#25](https://github.com/motherduckdb/terraform-provider-motherduck/pull/25)

## Verification
