## Highlights

- `motherduck_dive_embed_session` takes an optional `context` map. The embed session's token carries it, and secure view policies read each value with `session_context('key')`. One service account can then serve many viewers, each with its own row filter. [#142](https://github.com/motherduckdb/terraform-provider-motherduck/pull/142)
- The new `motherduck_short_lived_token` ephemeral resource mints a read scaling short-lived token, with an optional context, without writing the token to Terraform state. [#142](https://github.com/motherduckdb/terraform-provider-motherduck/pull/142)

## Upgrading from v0.4.3

Version constraints such as `~> 0.4.0` select this release. The new arguments are optional, so existing configurations keep their behavior.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. Existing resources are not expected to change.
3. Update pinned refs and module sources that reference `v0.4.3`.

## Features

- `motherduck_dive_embed_session` (ephemeral resource and data source) has a new optional `context` argument, a map of strings. [#142](https://github.com/motherduckdb/terraform-provider-motherduck/pull/142)
  - Secure view policies read a value with `session_context('key')`, which returns NULL for a key that the context does not set.
  - Keys may contain letters, digits, `_` and `.`. MotherDuck lowercases them, so two keys that differ only in letter case are rejected. A context holds at most 64 keys and 4096 bytes of keys and values.
  - The key `name` sets the session name and routes the session's requests to a read scaling replica. MotherDuck ignores `session_name` and `session_hint` when the context sets a name, so setting both fails with `Conflicting MotherDuck Dive embed session arguments`.
  - The provider checks these rules at plan time and reports `Invalid MotherDuck token context`. Values that are unknown during planning are checked at apply time, before the request is sent.
- New `motherduck_short_lived_token` ephemeral resource. [#142](https://github.com/motherduckdb/terraform-provider-motherduck/pull/142)
  - `token_type` is required and accepts `read_scaling`, the only type that MotherDuck mints. `context` follows the same rules as the embed session context.
  - MotherDuck mints the token for the identity behind the provider `admin_token`. The token expires after a day, and no later than the access token behind `admin_token`. Deleting that access token revokes the token.
  - The sensitive `token` and the `expire_at` time are available during the run only. A typical use is the `token` argument of an aliased `motherduck` provider.
  - The Pulumi bridge does not run ephemeral resources, so Pulumi programs mint these tokens through the MotherDuck REST API.
- The guide on securing shared rows and columns describes filtering by token context. Because a client can set its own connection context, a policy must also check the reader identity. The token value takes precedence only for the keys that the token sets. [#142](https://github.com/motherduckdb/terraform-provider-motherduck/pull/142)

## Compatibility

- Resource schemas, import formats and the provider source address are unchanged, apart from the new optional `context` argument.
