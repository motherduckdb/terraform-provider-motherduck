## Highlights

- `motherduck_role_grant` explains why MotherDuck refuses a grant or revoke in an organization that manages user roles through its identity provider. MotherDuck enforces this rule from its release of 2026-10-15. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
- When Terraform cannot reach MotherDuck, the error identifies a network, proxy, DNS or TLS problem rather than a token problem. TLS certificate verification failures are reported on the first attempt. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
- Table refresh detects letter case changes in ENUM labels and plans a replacement, which removes the rows of the table. Plans for tables with ENUM columns should be reviewed before they are applied. [#85](https://github.com/motherduckdb/terraform-provider-motherduck/pull/85)

## Upgrading from v0.3.4

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. No schema changed. A table whose live ENUM labels differ in letter case from the configuration now plans a replacement, which removes its rows. To keep the data, update the configured type to match the live type.
3. Update pinned refs and module sources that reference `v0.3.4`.

See [Compatibility](#compatibility) for the ENUM change.

## Bug Fixes

- Role grants in organizations that manage user roles through SCIM: [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
  - Previously, a refused grant or revoke showed only the message from MotherDuck, and a refused destroy gave no indication of how to proceed.
  - The error now states that grants to service accounts and roles remain available and that the roles of human users are managed in the identity provider. A refused destroy states that MotherDuck kept the grant and that `terraform state rm` stops managing the grant without revoking it.
- Connection failures: [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
  - Previously, `Could not connect to MotherDuck` did not indicate the cause, which led users to replace tokens that were valid. A TLS certificate verification failure could also be retried up to three more times before Terraform reported it.
  - The error now states that the machine cannot reach MotherDuck and that a new token does not resolve the problem. It includes the gRPC detail that names the failing step, such as DNS resolution or certificate verification. Certificate verification failures are reported without retries.
- ENUM label case drift on tables: [#85](https://github.com/motherduckdb/terraform-provider-motherduck/pull/85)
  - Previously, refresh treated an ENUM column whose labels differed only in letter case, such as `ENUM('open', 'closed')` and `ENUM('OPEN', 'closed')`, as unchanged. Terraform therefore kept a type that no longer matched the values the column accepts.
  - Refresh now detects the change, including in nested ENUM types, and plans a replacement.

## Compatibility

- Resource schemas, import formats and the provider source address are unchanged. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
- A `motherduck_table` whose live ENUM labels differ in letter case from the configuration now plans a replacement instead of no change. Replacing a table removes its rows. To keep the live type and its rows, set the configured type to match the live type before applying. [#85](https://github.com/motherduckdb/terraform-provider-motherduck/pull/85)
