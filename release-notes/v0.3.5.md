## Highlights

- `motherduck_role_grant` explains why MotherDuck refuses a grant or revoke when your organization manages user roles through its identity provider, which MotherDuck enforces from the release of 2026-10-15. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
- When Terraform cannot reach MotherDuck, the error now says it is a network, proxy, DNS or TLS problem and not a token problem. TLS certificate verification failures stop at the first attempt. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
- Table refresh detects case changes inside ENUM labels and plans a replacement, which removes the table's rows. Review plans for tables with ENUM columns before applying. [#85](https://github.com/motherduckdb/terraform-provider-motherduck/pull/85)

## Upgrading from v0.3.4

Constraints such as `~> 0.3.0` already select v0.3.5.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review it before applying. No schema changed. A table whose live ENUM labels differ in case from the configuration now plans a replacement, which removes its rows. Update the configured type to match the live one if you want to keep the data.

## Bug Fixes

- Role grants in organizations that manage user roles through SCIM. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
  - Before, a refused grant or revoke showed only MotherDuck's message, and a refused destroy left no clear way forward.
  - Now the error says that grants to service accounts and roles still work and that people's roles belong in the identity provider. A refused destroy says that MotherDuck kept the grant and that `terraform state rm` stops managing it without revoking it.
- Connection failures. [Change](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.3.4...v0.3.5)
  - Before, `Could not connect to MotherDuck` gave no hint of the cause, and users often replaced a working token. A TLS certificate verification failure could also be retried up to three more times before Terraform reported it.
  - Now the error says the machine cannot reach MotherDuck and that a new token does not help. MotherDuck's extension now includes the gRPC detail that names the failing step, such as DNS resolution or certificate verification. Certificate verification failures are reported without retrying.
- ENUM label case drift on tables. [#85](https://github.com/motherduckdb/terraform-provider-motherduck/pull/85)
  - Before, refresh treated an ENUM column whose labels differed only in case, such as `ENUM('open', 'closed')` and `ENUM('OPEN', 'closed')`, as unchanged, so Terraform kept a type that no longer matched the values the column accepts.
  - Now refresh detects the change, including in nested ENUM types, and plans a replacement. Replacing a table removes its rows, so review the plan, or update the configured type to match the live one to keep the data.
