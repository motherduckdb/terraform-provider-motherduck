## Highlights

- `motherduck_table` adds and drops columns in place and keeps the rows in the other columns. Previously, every column change replaced the table and its data. [#121](https://github.com/motherduckdb/terraform-provider-motherduck/pull/121)
- `motherduck_secret` accepts write-only arguments that keep secret values out of the Terraform plan and state. [#122](https://github.com/motherduckdb/terraform-provider-motherduck/pull/122)
- A SQL statement that MotherDuck does not answer is canceled after 30 minutes instead of blocking the run indefinitely. [#120](https://github.com/motherduckdb/terraform-provider-motherduck/pull/120)

## Upgrading from v0.3.x

v0.4.0 is a minor release because it changes how existing `motherduck_table` configurations are planned and bounds the duration of SQL statements. Under pre-1.0 versioning, constraints such as `~> 0.3.0` do not select it, so `terraform init -upgrade` remains on v0.3.x until the constraint is changed.

1. Change the provider constraint to `~> 0.4.0` and run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. Existing resources are not expected to change.
3. Review the configuration against the changes under [Compatibility](#compatibility):
   - Adding or dropping a `motherduck_table` column now plans an in-place update instead of a replacement.
   - A SQL statement without a resource timeout is canceled after 30 minutes.
4. Update pinned refs and module sources that reference `v0.3.12`.

## Features

- `motherduck_table` changes in place where MotherDuck supports it: [#121](https://github.com/motherduckdb/terraform-provider-motherduck/pull/121)
  - Adding a key to `columns` adds the column, and removing a key drops it. The rows in the other columns are kept.
  - The new optional `column_order` argument sets the order of the columns when the table is created.
  - The new optional `primary_key` argument sets the primary key when the table is created.
  - The new optional `not_null` argument lists the columns that reject `NULL` and can change in place.
  - When one of these arguments is omitted, the provider records the value that MotherDuck reports and does not change it.
- `motherduck_secret` accepts `params_wo` and `flight_params_wo`, the write-only forms of `params` and `flight_params`. Terraform sends the values to MotherDuck and stores them in neither the plan nor the state. The new `params_wo_version` argument writes the current values to MotherDuck when its number changes. Write-only arguments require Terraform 1.11 or later. The [secret documentation](https://github.com/motherduckdb/terraform-provider-motherduck/blob/main/docs/resources/secret.md) describes how to move an existing secret. [#122](https://github.com/motherduckdb/terraform-provider-motherduck/pull/122)
- Refreshing `motherduck_service_account` resources reuses one listing of the organization's users for up to one minute instead of requesting the full listing once for each service account. Refresh is faster in organizations with many users and service accounts. [#120](https://github.com/motherduckdb/terraform-provider-motherduck/pull/120)

## Bug Fixes

- A SQL statement that MotherDuck never answered blocked `terraform plan` or `terraform apply` until the process was interrupted, unless the resource had a `timeouts` block. Such a statement is now canceled after 30 minutes with the diagnostic "MotherDuck SQL statement did not finish within 30m0s and was canceled". [#120](https://github.com/motherduckdb/terraform-provider-motherduck/pull/120)

## Compatibility

- Resource schemas gain optional arguments only. Import formats and the provider source address are unchanged.
- `motherduck_table` plans differ from v0.3.x: [#121](https://github.com/motherduckdb/terraform-provider-motherduck/pull/121)
  - Adding or dropping a column is an in-place update. Dropping a column deletes the data in that column. Renaming a key in `columns` drops the old column and adds an empty one, so the plan should be reviewed before it is applied.
  - A column added in place is appended after the existing columns. Statements that depend on column position should use explicit column lists, or the configuration should set `column_order`.
  - A different type for an existing column, a different `primary_key`, a different order of existing columns and a column name that changes only in letter case still replace the table.
  - DuckLake databases do not support primary keys, so `primary_key` must stay unset for tables in them.
- A SQL statement that runs longer than 30 minutes is canceled when the resource has no `timeouts` block. Resources that support `timeouts` keep the configured duration, which can be raised for long operations. [#120](https://github.com/motherduckdb/terraform-provider-motherduck/pull/120)
- `params_wo` and `flight_params_wo` cannot be combined with `params` and `flight_params`, and they require `params_wo_version`. Terraform versions earlier than 1.11 reject configurations that set a write-only argument. [#122](https://github.com/motherduckdb/terraform-provider-motherduck/pull/122)
