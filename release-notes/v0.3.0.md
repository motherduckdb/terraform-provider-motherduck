## Highlights

- An existing Iceberg REST catalog, such as Amazon S3 Tables or AWS Glue, can be registered as a MotherDuck database with `database_type = "iceberg"` and an `iceberg` block. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- The provider manages the MotherDuck features released through 2026-09-25: `FLIGHTS` secrets, access token descriptions, the current Dive embed session fields and Flight schedule status. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Release packages run on Linux with glibc 2.34 or later, including Ubuntu 22.04, Debian 12, RHEL 9 and Amazon Linux 2023, and on macOS 13 or later. The v0.2.13 packages required glibc 2.38 and macOS 15. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)

## Upgrading from v0.2.x

v0.3.0 is a minor release because it changes behavior that existing configurations can depend on. Under pre-1.0 versioning, constraints such as `~> 0.2.13` do not select it, so `terraform init -upgrade` remains on v0.2.x until the constraint is changed.

1. Change the provider constraint to `~> 0.3.0` and run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it.
3. Review the configuration against the changes under [Compatibility](#compatibility):
   - Values that MotherDuck rejected at apply time now fail at plan time: short service account usernames, reserved token names, reserved Flight configuration keys, and oversized Flight source code or requirements.
   - Provider arguments that were ignored when unknown now produce errors.
   - The `motherduck_flight_logs` data source returns a different window when `limit` is set.
   - Removing a Duckling cooldown from the configuration no longer resets it.
   - `session_hint` is deprecated in favor of `session_name`.
   - The `motherduck_guide_grantees` data source no longer has a `granted_at` column.
4. Update module sources that reference `?ref=v0.2.13`. The blueprint modules and the example links in the guides reference `v0.3.0`.

## Features

- `motherduck_secret` accepts a sensitive `flight_params` map for secrets with `type = "flights"`. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- `motherduck_access_token` accepts an optional `description`, and the `motherduck_user_tokens` data source returns it. MotherDuck cannot edit a description, so changing it replaces the token. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- The `motherduck_dive_embed_session` data source and ephemeral resource accept `session_name`, `version`, `required_resources` and `initial_state`. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- `motherduck_flight` reports `schedule_status` and `owner_name`, so a schedule that MotherDuck disabled is visible. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- The `motherduck_flight_logs` data source pages on the server and accepts `order`, so log lines before the last 1,000 can be read. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- The `motherduck_files`, `motherduck_buckets_for_secret` and `motherduck_flight_logs` data sources accept `limit` and `offset`. Every listing data source documents a deterministic row order. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)

## Bug Fixes

- Changing the `include_pattern` of a share now updates the share in place. Previously, omitted share options forced a replacement that dropped the share, changed its URL and removed its grants. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Writing the column type of an imported table with an alias, such as `INT` for `INTEGER`, no longer replaces the table. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- A named snapshot whose database was dropped outside Terraform remains in state with a warning, and destroying it releases the retained snapshot name, which is billed. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Snapshot refresh follows `snapshot_id`, so a rename made outside Terraform plans an in-place rename back to the configured name. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Secrets with upper-case names are found after creation, and destroying a secret that no longer exists succeeds. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Creating a view fails instead of overwriting an existing view with the same name. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Guide creation is no longer retried. Previously, a retry after a timeout could create duplicate Guides. A failed read after creation no longer writes unknown values to state. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Guide `references` treat an empty `schema`, `table` or `column` string the same as an omitted value. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- `motherduck_dive` reads `api_version` and `required_resources` on refresh and import, so an imported Dive no longer requires a corrective update. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- `motherduck_flight_run` keeps its state while the parent Flight exists. Previously, a run that was not on the first listing page was removed from state, and the Flight ran again. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Duckling configuration cooldowns record the live value, so import and refresh no longer plan an update. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Catalog row JSON keeps integers exact and renders DECIMAL, INTERVAL and nested UUID values correctly. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- The SQL client observes cancellation while it waits for a connection and discards a connection whose database could not be restored. The REST client does not retry POST requests. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)

## Compatibility

- Stricter plan-time validation. MotherDuck already rejected each of the following values at apply time: [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
  - Service account usernames must have at least 3 characters.
  - The reserved token names `MotherDuck Extension` and `MotherDuck Flights` are rejected.
  - The reserved Flight configuration keys `MOTHERDUCK_FLIGHT_ID` and `MOTHERDUCK_FLIGHT_RUN_ID` are rejected.
  - Flight source code and requirements have size limits.
- Unknown values for the provider arguments `api_base_url`, `database`, `attach_mode` and `custom_user_agent` now produce errors. An `api_base_url` that uses plain HTTP is accepted only for loopback hosts. Provider arguments must be known at plan time. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- When `limit` is set on the `motherduck_flight_logs` data source, rows are counted from the start of the log instead of from the start of the last 1,000 lines. Set `order = "desc"` to read the most recent lines. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Removing a configured Duckling cooldown keeps the current value instead of resetting it. Set the intended value explicitly. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- `session_hint` on the Dive embed session is deprecated in favor of `session_name`. Configurations should move to `session_name`. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- The `motherduck_guide_grantees` data source no longer has a `granted_at` column. Configurations that reference the column must remove the reference. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
- Guide role access remains experimental and is not yet available in MotherDuck. [Changes](https://github.com/motherduckdb/terraform-provider-motherduck/compare/v0.2.13...v0.3.0)
