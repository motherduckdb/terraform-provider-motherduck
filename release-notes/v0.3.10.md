## Highlights

- Changing only the ASCII letter case of a `motherduck_secret` name, for example from `MySecret` to `MYSECRET`, now updates the secret in place. Previously the plan replaced the secret, and with `create_before_destroy` the apply failed because the secret already existed. [#108](https://github.com/motherduckdb/terraform-provider-motherduck/pull/108)
- The `motherduck_secret` resource and data source now read the secret that MotherDuck resolves the configured name to, including when two secret names differ only in the case of a non-ASCII letter. [#108](https://github.com/motherduckdb/terraform-provider-motherduck/pull/108)

## Upgrading from v0.3.9

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. A pending change to the letter case of a secret name now plans an in-place update instead of a replacement. Other existing resources are not expected to change.
3. Update pinned refs and module sources that reference `v0.3.9`.

## Bug Fixes

- MotherDuck stores a secret name with the letters A to Z lowered, so `MySecret` and `MYSECRET` name the same secret. A `motherduck_secret` whose `name` changed only in ASCII letter case previously planned a replacement, which failed with "already exists" under `create_before_destroy`. The change is now an in-place update, and the resource `id` follows the configured spelling. Any other change to `name`, including a change in the case of a non-ASCII letter, still replaces the secret. [#108](https://github.com/motherduckdb/terraform-provider-motherduck/pull/108)
- MotherDuck treats names such as `Äpfel` and `äpfel` as two different secrets, but the provider looked secrets up with a comparison that ignored the case of every letter. When both secrets existed, refresh and the `motherduck_secret` data source could return the type, provider and scope of the other secret. Lookups now prefer the secret whose stored name matches the configured name, as MotherDuck does. [#108](https://github.com/motherduckdb/terraform-provider-motherduck/pull/108)

## Compatibility

- Resource schemas, import formats and the provider source address are unchanged. The `motherduck_secret` resource `id` now changes with the letter case of `name` instead of keeping the spelling used at creation. Configurations that reference the `id` see the new spelling after the update. [#108](https://github.com/motherduckdb/terraform-provider-motherduck/pull/108)
