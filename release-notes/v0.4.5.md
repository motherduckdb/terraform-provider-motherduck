## Highlights

- An access token that is revoked or expired and used as the provider `token` now fails with `MotherDuck rejected the SQL token`, include the error message returned by MotherDuck, and advise users to check or replace the token rather than reporting a network connectivity problem. [#145](https://github.com/motherduckdb/terraform-provider-motherduck/pull/145)
- Network connectivity failures on the same request, such as `UNAVAILABLE` responses, retain the connectivity diagnostic so operators can distinguish authentication errors from transport issues. [#145](https://github.com/motherduckdb/terraform-provider-motherduck/pull/145)

## Upgrading from v0.4.4

Because this release is a patch update in the `0.4` series, version constraints such as `~> 0.4.0` select it automatically. Only the diagnostic message for revoked or expired access tokens changes, so existing configurations retain their behavior.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. Existing resources are not expected to change.
3. Update pinned refs and module sources that reference `v0.4.4`.

## Bug Fixes

- Previously, when the provider `token` argument or the `MOTHERDUCK_TOKEN` environment variable contained a revoked or expired access token, MotherDuck refused to exchange it for a session token and returned `Could not connect to MotherDuck` with status `PERMISSION_DENIED`. The provider then appended a note stating that Terraform could not reach MotherDuck due to a network, proxy, DNS, or TLS problem and that replacing the token would not help. The provider now reports `MotherDuck rejected the SQL token`, instructs users to check the provider `token` argument or the `MOTHERDUCK_TOKEN` environment variable and confirm the token has not expired or been revoked, and includes the message returned by MotherDuck. Network failures such as `UNAVAILABLE` responses continue to include the connectivity note, and malformed tokens continue to be reported as rejected tokens. The existing `MotherDuck rejected the SQL token` entry in the troubleshooting guide applies to this diagnostic. [#145](https://github.com/motherduckdb/terraform-provider-motherduck/pull/145)

## Compatibility

- Resource schemas, Terraform state, and execution plans are unchanged in this release, so no configuration or state migration is required. [#145](https://github.com/motherduckdb/terraform-provider-motherduck/pull/145)
- The diagnostic wording for revoked or expired access tokens changes from the connectivity note to `MotherDuck rejected the SQL token`. Teams with automated log parsing or alerting rules that match the previous error text should update those rules to match `MotherDuck rejected the SQL token`. [#145](https://github.com/motherduckdb/terraform-provider-motherduck/pull/145)
