## Highlights

- A revoked or expired access token now fails with `MotherDuck rejected the SQL token` and the advice to replace the token. Earlier versions reported it as a network problem and stated that replacing the token would not help. [#145](https://github.com/motherduckdb/terraform-provider-motherduck/pull/145)

## Upgrading from v0.4.4

Version constraints such as `~> 0.4.0` select this release. Only the wording of one diagnostic changes, so existing configurations keep their behavior.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. Existing resources are not expected to change.
3. Update pinned refs and module sources that reference `v0.4.4`.

## Bug Fixes

- When the provider `token` was a revoked or expired access token, MotherDuck refused to exchange it for a session token, and the error read `Could not connect to MotherDuck` with the status `PERMISSION_DENIED`. The provider then added a note that the failure was a network, proxy, DNS, or TLS problem and that replacing the token would not help. The provider now reports `MotherDuck rejected the SQL token` with the MotherDuck message, and directs users to supply a valid token. Network failures on the same request keep the connectivity note. [#145](https://github.com/motherduckdb/terraform-provider-motherduck/pull/145)
