## Highlights

- SQL operations no longer fail after the database named by the provider `database` argument is dropped during the same run. [#117](https://github.com/motherduckdb/terraform-provider-motherduck/pull/117)
- The `name` filter of the `motherduck_secrets` data source now returns only the secret that MotherDuck resolves the name to. [#116](https://github.com/motherduckdb/terraform-provider-motherduck/pull/116)

## Upgrading from v0.3.11

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it. Existing resources are not expected to change. A `motherduck_secrets` data source with a `name` filter can return fewer rows, as described under [Compatibility](#compatibility).
3. Update pinned refs and module sources that reference `v0.3.11`.

## Bug Fixes

- The provider selects the database from its `database` argument on every new SQL connection. When that database had been dropped, for example by destroying the `motherduck_database` resource that manages it, a connection opened later in the same run failed with "select default database on new connection", and every remaining SQL operation in the run failed with it. A new connection now keeps the DuckDB default database when the configured database no longer exists. [#117](https://github.com/motherduckdb/terraform-provider-motherduck/pull/117)
- MotherDuck treats names such as `Äpfel` and `äpfel` as two different secrets, but the `name` filter of the `motherduck_secrets` data source ignored the case of every letter and returned both. The filter now applies the same rule as the `motherduck_secret` resource and data source and returns the secret whose stored name matches the configured name. [#116](https://github.com/motherduckdb/terraform-provider-motherduck/pull/116)

## Compatibility

- Resource schemas, import formats and the provider source address are unchanged. A `motherduck_secrets` data source whose `name` filter matched several secrets that differ only in the case of a non-ASCII letter now returns one row. Configurations that relied on the additional rows need a separate data source for each name. [#116](https://github.com/motherduckdb/terraform-provider-motherduck/pull/116)

## Maintenance

- A new [troubleshooting guide](https://github.com/motherduckdb/terraform-provider-motherduck/blob/main/docs/guides/troubleshooting.md) lists common provider diagnostics with their causes and resolutions. [#117](https://github.com/motherduckdb/terraform-provider-motherduck/pull/117)
- Contributor tooling: [#117](https://github.com/motherduckdb/terraform-provider-motherduck/pull/117)
  - Terraform, OpenTofu and Pulumi CLI downloads in the test scripts are retried after a transient HTTP error.
  - The contract test suite has a 10 minute timeout instead of 5 minutes, which it could exceed on a loaded machine.
  - `AGENTS.md` describes the package layout and the focused test commands.
  - Dependabot no longer updates the `pulumi` package of the Pulumi example on its own, because that pin must match the Pulumi CLI version used by the test scripts.
