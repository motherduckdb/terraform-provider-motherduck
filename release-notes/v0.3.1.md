## Highlights

- Recover from failed snapshot creation without leaving a named snapshot retained after destroy. [#69](https://github.com/motherduckdb/terraform-provider-motherduck/pull/69)

## Features

- Read metadata for a separately owned secret with `data.motherduck_secret`. A missing prerequisite fails clearly without adopting it or copying credentials into state. [#68](https://github.com/motherduckdb/terraform-provider-motherduck/pull/68)

## Bug Fixes

- Reject null or blank snapshot catalog IDs and recover a missing ID from the saved database and name before clearing the name. Failed or ambiguous recovery reads stop cleanup, including destroy with refresh disabled. [#69](https://github.com/motherduckdb/terraform-provider-motherduck/pull/69)

- Keep snapshot state when its ID is missing and recovery metadata is unlisted. Missing metadata no longer silently completes destroy or forgets cleanup state. [#70](https://github.com/motherduckdb/terraform-provider-motherduck/pull/70)

Snapshot readback now reports an error when the catalog returns an unusable ID. [#68](https://github.com/motherduckdb/terraform-provider-motherduck/pull/68), [#69](https://github.com/motherduckdb/terraform-provider-motherduck/pull/69)

## Upgrading

Run `terraform init -upgrade` with a constraint that permits v0.3.1, then review `terraform plan`. Constraints such as `~> 0.3.0` already permit this patch. If a snapshot create failed after its remote write, retry the apply or destroy after catalog reads recover. The saved database and name can now resolve its missing ID. Permission, ambiguity and unresolved-ID errors still require attention. If you confirm the remote name was already cleared, explicitly remove its remaining state entry.
