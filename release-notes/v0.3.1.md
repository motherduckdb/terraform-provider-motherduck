## Highlights

- A failed snapshot creation no longer leaves a named snapshot retained after destroy. [#69](https://github.com/motherduckdb/terraform-provider-motherduck/pull/69)
- The new `motherduck_secret` data source reads the metadata of a secret that is managed elsewhere. [#68](https://github.com/motherduckdb/terraform-provider-motherduck/pull/68)

## Upgrading from v0.3.0

Version constraints such as `~> 0.3.0` select this release.

1. Run `terraform init -upgrade`.
2. Run `terraform plan` and review the plan before applying it.
3. If a snapshot create failed after MotherDuck created the snapshot, retry the apply or destroy once catalog reads succeed. The saved database and name now resolve the missing snapshot ID. Permission errors, ambiguous identities and unresolved IDs still require attention. If the snapshot name is confirmed to be cleared in MotherDuck, remove the remaining entry from state with `terraform state rm`.
4. Update pinned refs and module sources that reference `v0.3.0`.

## Features

- The `motherduck_secret` data source reads the metadata of a separately owned secret. A missing secret fails with a clear error, and the data source neither adopts the secret nor copies credentials into state. [#68](https://github.com/motherduckdb/terraform-provider-motherduck/pull/68)

## Bug Fixes

- Snapshot catalog reads that return a null or blank snapshot ID are now rejected. A missing ID is recovered from the saved database and name before the snapshot name is cleared. A failed or ambiguous recovery stops the cleanup, including a destroy that runs without refresh. [#69](https://github.com/motherduckdb/terraform-provider-motherduck/pull/69)
- A snapshot whose ID is missing and whose recovery metadata is not listed now remains in state. Previously, the missing metadata could complete a destroy without clearing the snapshot, or remove the cleanup information from state. [#70](https://github.com/motherduckdb/terraform-provider-motherduck/pull/70)

## Compatibility

Snapshot reads now report an error when the catalog returns an unusable ID.
